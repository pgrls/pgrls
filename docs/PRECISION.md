# pgrls precision corpus

Generated by `python -m corpus.measure` (pgrls 0.54.0). Do not edit by hand — re-run the script.

## What this is

An **adjudicated** corpus of small, self-contained schemas, each linted through the real introspection + rule path with the full built-in rule set at default options (no `disable`, no allowlists). Every case carries the complete set of rule IDs that *should* fire; anything else that fires is a false positive, anything missing is a false negative.

The negatives are deliberately **adversarial** — `coalesce()`-wrapped auth checks, `IS NULL` buried in subqueries or under `AND`, predicates wrapped in `SubLink`s — the exact shapes that bait false positives. A clean schema that trivially fires nothing would prove nothing.

> **Scope caveat.** This measures *construct validity* — whether pgrls fires correctly on hand-labeled cases. It is **not** a random sample of real-world databases, so these are a precision/recall characterization of this labeled set, not an estimate of the false-positive rate over all Postgres schemas in the wild. The two artifact-dependent rules (HYG004 coverage, PERF005 runtime stats) need data a static schema doesn't have and are out of scope.
